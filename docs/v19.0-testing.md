# Domain Controller v19.0 testing

## Scope and source

The appliance uses Samba, Kerberos, CUPS, Lighttpd, and supporting packages
from signed Debian Trixie and TurnKey v19 APT repositories. Samba is the
identity-defining application; its practical updater is signed APT metadata
plus a non-mutating upgrade simulation.

The v19 migration is based on frozen candidate
`ecc3ab330697175ff5115ed3f465ca3bc6ddf9cf`. Two of six product loops were
used. The first removes the administrator password from both OS
process-argument boundaries and from console and failure-log command
retention. Firstboot sends the password on stdin. Provisioning calls Samba's
public Python entry point in-process and redacts reflected output before it can
reach logs. The second adds a bounded, secret-safe wait for the newly started
KDC before firstboot completes.

Inherited Core v19 checks cover normal init, multi-user target, SSH, cron,
Trixie identity, common firstboot fencing, and baseline Webmin behavior. This
appliance's own test covers its modified firstboot, identity, DNS, Kerberos,
Samba, CUPS default, service restart, authenticated data path, join path, and
updater boundary.

## Evidence and limitations

The 20/80 release-QA disposition is PASS for independent review at product
loop 2/6. Exact run `20260829t143424z-889129-6408` used source commit
`acbebba4ee0f851c2fcf4e0e6a32286c136418e9` (archive SHA-256
`4a8c420bf9b2a3c4a4b9cd2506e07fce8274f62aea6c930003259f943711a625`)
and private harness `57781efa2f98385a6b6593339a358dd3a866be4c` (archive SHA-256
`38644d4f9c3ff0c6363ea6d824432a26eaef81b96f905cf0996101e3bd16dfbc`).
The configured-root overlayfs attempt returned status 32 and the documented
fallback built and imported successfully. The runtime reached healthy
multi-user state, completed the Domain Controller firstboot hook, passed the
password non-disclosure regression, service/CUPS checks, AD role/realm/domain
identity, keytab permissions, and authoritative Samba DNS.

The harness retained the run as FAIL only because the test then used
`Administrator@LOCALHOST.LAN` instead of the canonical working
`administrator` principal. Commit `64bdae2` corrects that test-only mismatch;
the user-directed 20/80 boundary explicitly avoids another full build for it.
Consequently the authenticated Netlogon round trip, disposable second-DC join,
restart, web, and APT simulation remained unreached and are residual release
checks, not observed product failures. Cleanup, container identity, and disk
checks were all zero. Retained evidence is under
`/home/agent/.local/state/non-liraz-v19-release-qa/domain-controller/failures/domain-controller/current`;
`report.txt` SHA-256 is
`bce990e24a4baf58be7cfd87525c983552b607eaee502ce42a9859a4e94ed68c`,
`run.log` SHA-256 is
`b317607bd80ddac8263f7149d433dacf359f70006943e07e027e2a07a69a00d5`,
and every retained manifest entry verifies.

The Docker gate does not exercise installer, kernel, physical printer, or a
Windows desktop. The local authenticated SMB round trip, Kerberos ticket, DNS
query, and disposable Samba DC join exercise the appliance side without an
external Windows fixture.
